3. 核心缺陷深度分析

3.1 PlaywrightAgent 的根本问题

🔩 硬编码策略

所有入口查找关键词（师资/教师/faculty/staff）都是硬编码的。遇到"人才队伍"、"教学科研人员"等变体就完全找不到。

🐢 单线程低效

信号量 Semaphore(2) 限制同时只爬 2 个详情页。对于 100+ 教师的学院，大量时间浪费在等待。

🔍 邮箱提取策略单一

只靠正则匹配，反爬处理只有 5 种 [at] 变体。无法处理图片验证码、JS 动态渲染、自然语言指令。

🧠 无状态无记忆

每次任务从头开始。不记录哪个策略成功、哪些 URL 模式有效、哪些反爬模式出现过。

7. 总结

为什么不如 Claude Code / Hermes？

UniEmailAgent 是一个"工具"而不是一个"智能体"。

对比项 UniEmailAgent Claude Code / Hermes
本质爬虫脚本 + CLI 包装通用智能体框架
记忆❌ 无（每次清空）✅ 有（持久上下文）
学习❌ 无（硬编码规则）✅ 有（经验累积）
规划❌ 固定流程✅ 动态规划
适应❌ 0（遇到新结构就失败）✅ 强（理解+推理+适应）

最关键的三件事

1. 增加持久记忆

Agent 需要记住什么策略有效、什么策略失败。这是从"每次从零开始"到"经验累积"的关键跨越。

2. 增加反馈循环

Agent 需要能在失败后自动切换策略。策略A失败 → 策略B → 策略C，而不是"跳过"。

3. 多 Agent 协作

专业分工才能处理复杂任务。结构分析 + 执行爬取 + 数据验证，三个臭皮匠顶个诸葛亮。

最大的误区

"加了更好的提示词 = Agent 就更聪明" — 错

ClaudeAgent 本身就是 Claude Code，提示词是 Claude Code 写的。问题是：

  • 它没有记忆 → 下次任务又忘了上次的教训
  • 它没有工具 → 只会 Read/Write/Bash，没有专用爬虫工具
  • 它没有编排 → 只能顺序执行，不能并行搜索+验证

💡 提示词只能占到智能水平的 20%，剩下的 80% 在架构（记忆、工具、编排、学习）。
